The answer first

一句話：我寫的是什麼？

FinScope TW 不是把問題直接丟給 Gemini。它是一個有資料來源、有工具邊界、有登入驗證、看得到研究軌跡的台股研究 Agent。

Project thesis
我把 Java 台股資料系統變成可被 AI 呼叫的 MCP Server，再用 Python 建立會選工具、查來源、處理失敗、保留證據的研究 Agent。

使用者得到的不是「AI 猜測」

  • 即時行情來自 TWSE MIS
  • 月營收來自 FinMind
  • 近期事件附公開新聞來源
  • 畫面顯示每個 tool 與耗時
  • 資料不足時明說限制
  • 不預測股價、不提供買賣指令

Trace one request

問「台積電近期如何？」之後

點選 1–7，看一次真實 research request 在程式裡如何流動。這就是不用讀完整 repository 也能理解的「正確介面」。

01

先確認使用者，不讓匿名請求直接消耗模型。

FastAPI 從同源 cookie 取得 Java 簽發的 JWT，驗證 signature、subject 與 expiry。瀏覽器 JavaScript 讀不到 token。

app/auth/session.py · app/api/session.py
Actual boundaryBrowser → HttpOnly + SameSite=Lax cookie FastAPI → jwt.decode(... require: sub, exp) No valid session → HTTP 401 POST /api/research → 6 requests / minute
02

把金融回答規則寫進 system policy。

即時價格一定要查 snapshot；營收問題才查 revenue；近期事件要查 news；不得修改工具數字、猜股票代碼或把相關性寫成因果。

app/agent/orchestrator.py · SYSTEM_PROMPT
Policy examples價格 → 必須 get_stock_snapshot 營收趨勢 → get_revenue_history 近期事件 → search_news 輸出 → 摘要 / 關鍵數據 / 可能因素 / 資料限制
03

Gemini 只能從允許清單選工具。

模型看得到三個 function schema 與參數限制；它不知道 X-Agent-Key、JWT secret 或資料庫連線資訊。

app/tools/definitions.py · app/clients/gemini.py
Allowed toolssearch_news(query, days 1..30, max_results 1..10) get_stock_snapshot(stock_code: ^[0-9]{4}$) get_revenue_history(stock_code, months 1..24)
04

Python 執行工具；股票資料透過 MCP 交給 Java。

新聞由 Python 讀 Google News RSS。行情與營收透過可重用的 MCP session 呼叫 Java，並用 X-Agent-Key 保護服務。

app/tools/executor.py · app/clients/stocktracker.py · StockMcpTools.java
Data ownershipsearch_news → Google News RSS get_stock_snapshot → MCP → Java → TWSE MIS get_revenue_history → MCP → Java → FinMind Java result → structured JSON, not prose
05

工具 JSON 回到同一個 interaction。

Gemini 依已取得的證據決定是否需要下一個工具或完成回答。多個同輪 tool calls 會以 asyncio.gather 並行執行。

ResearchOrchestrator.research()
Observable traceToolExecution { name, arguments, result, status, duration_ms, error } → function_result → Gemini continuation
06

資料源壞掉時，不讓模型一直重試或補答案。

如果 tool 失敗，下一輪移除工具，要求模型說明限制；Agent 最多三輪。沒有足夠資料時回傳 bounded fallback，而不是推測。

app/agent/orchestrator.py · _bounded_fallback_answer()
Fail-closed behaviorany tool failed → next_tools = [] max rounds = 3 no verified data → 「不提供推測性結論」 provider 429 → bounded retry + Retry-After
07

前端不只秀答案，也秀答案的來歷。

ResearchResponse 同時包含 answer、tool calls、citations、model 與 disclaimer。前端將 deterministic data 畫成圖表，並列出每個工具與耗時。

app/schemas/research.py · app/static/app.js
User-visible evidence研究摘要 + 資料限制 價格 / 月營收 dashboard 研究軌跡：tool + arguments + duration + status 引用來源：title + URL 金融資訊免責聲明

Safety and failure

真正重要的不是 happy path

這些 guardrails 是程式直接掌握的，不交給 LLM 自律。

安全邊界

  • 研究端點需要有效會員 session
  • JWT 放 HttpOnly / SameSite=Lax cookie
  • MCP 使用獨立 X-Agent-Key
  • 工具唯讀，沒有下單能力
  • 股票代碼與月份有 schema / domain 驗證
  • 公開 demo 每 IP 每分鐘最多 6 次研究

失敗處理

  • Gemini 429 有上限重試與 Retry-After
  • Java cold start 先 health readiness 再 MCP
  • timeout / HTTP / invalid JSON 正規化
  • tool 失敗後停止繼續呼叫
  • 三輪上限避免無限 Agent loop
  • 資料不足時回覆限制，不編造數字

executions = await asyncio.gather(
  *(executor.execute(
      call.id, call.name, call.arguments
    ) for call in turn.function_calls)
)

next_tools = (
  [] if any(x.status != "success"
     for x in executions)
  else self._tools
)

JavaStockMcpTools.java
@Tool(
  name = "get_stock_snapshot",
  description = "取得台灣股票最新行情..."
)
public StockSnapshotToolResult getStockSnapshot(
    @ToolParam String stockCode) {
  return StockSnapshotToolResult.from(
      service.getSnapshot(stockCode));
}
證明：模型只看到穩定 tool contract；行情解析與計算仍由 Java domain service 負責。
