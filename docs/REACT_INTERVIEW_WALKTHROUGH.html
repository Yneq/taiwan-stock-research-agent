React、型別與測試。

這是一份根據本專案實際程式碼製作的複習導覽。React 客戶端讓會員輸入台股問題，呼叫既有 FastAPI，呈現研究摘要、工具軌跡及來源。

前端使用說明Python 專案Java 資料服務既有線上展示

使用者的問題由 React 管理互動；資料仍由原本的 Python 與 Java 服務提供。

1. 表單受控 textarea、至少 3 字、送出時避免重送 2. 會員狀態先查 session；未登入就暫存問題並提供體驗登入 3. 研究請求hook 管理 loading、success、error 4. 證據呈現摘要、工具狀態和公開來源分開顯示

系統邊界

Browser / React → FastAPI /api/research → Python 規劃查詢 → Java MCP 與新聞 → Gemini 單次整理 → React 結果卡。

React 不直接呼叫 Gemini、Java MCP 或資料庫，也沒有讀取 JWT 的程式碼。

實際端點

GET /api/session/status 查會員；POST /api/session/demo 建立體驗 session；POST /api/research 送出問題。Vite 在本機將 /api 代理到 FastAPI。

元件地圖

App 負責會員狀態及流程協調；ResearchForm 只處理輸入；useResearch 處理研究請求狀態；ResearchResult 只負責展示；api/research.ts 負責 HTTP。這種拆分讓測試能從使用者行為開始，也能單獨定位 API 與畫面問題。

受控表單：useState

textarea 的值永遠來自 React state。輸入變更只更新 state，送出再做 trim 和長度檢查。

const [question, setQuestion] = useState("");
const valid = question.trim().length >= 3;

<textarea value={question}
  onChange={(event) => setQuestion(event.target.value)} />

這證明表單狀態有單一來源；按鈕是否可按、字數顯示都能由同一個值推導。

初始化與清理：useEffect

元件掛載後查一次 session。依賴陣列 [] 表示這段 effect 不依賴可變 props/state；清理時 abort 尚未完成的請求。

useEffect(() => {
  const controller = new AbortController();
  getSession(controller.signal).then(setMember);
  return () => controller.abort();
}, []);

這是便於講解的節錄；實際程式還處理 error 與 loading。研究表單是使用者事件，因此從 submit handler 發送，沒有靠 effect 監看問題文字。

props 與責任

ResearchForm 接收 busy: boolean 和 onSubmit: (question: string) => void。它不需要知道 API、會員或 JWT。ResearchResult 接收具型別的 ResearchResponse，只依資料渲染。這是用 props 表達元件契約的例子。

狀態的型別聯集

status 是辨識欄位。只有成功狀態有 result，錯誤狀態才有 message。TypeScript 會在條件分支裡縮小型別。

type ResearchState =
  | { status: "idle" }
  | { status: "loading" }
  | { status: "success"; result: ResearchResponse }
  | { status: "error"; message: string; needsLogin: boolean };

這證明畫面不必用多個可能互相矛盾的布林值，例如 loading=true 同時 error=true。

API 契約與限制

ResearchResponse 對照 FastAPI 的 Pydantic schema：answer、tool_calls、citations、model、disclaimer。HTTP 非 2xx 轉成有 status 的 ApiError，401 可獨立處理。

if (!response.ok) throw await readError(response);
return response.json() as Promise<ResearchResponse>;

TypeScript 型別只在編譯期檢查；這個 as 不是執行期 JSON 驗證。若 API 契約頻繁變動，可加入 Zod 等執行期驗證。

安全與失敗邊界

前端請求同源 /api，瀏覽器自動帶上 HttpOnly session cookie；前端 JavaScript 讀不到 cookie 裡的 JWT。Demo 帳密在伺服器設定，沒有放在 React。401 提示重新登入；502 呈現後端 detail；網路錯誤會進 error 狀態。引用連結只允許 HTTP(S) URL，並使用 noopener noreferrer。
